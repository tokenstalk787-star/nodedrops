
# NodeDrops Listing Verification Policy

## 1. Evidence standards

Every public opportunity should have a trustworthy source. Prefer:
- The project's official website and documentation
- Official announcements and blog posts
- Official repositories and release notes
- Official testnet, node, or developer-program documentation

Community posts may help discover an opportunity, but should not be the sole evidence for a confirmed reward.

## 2. Incentive labels

- CONFIRMED: The project has explicitly announced an incentive.
- POTENTIAL: There are credible reasons to monitor the opportunity, but a reward is not guaranteed or officially confirmed.
- NOT_ANNOUNCED: No reliable public reward announcement has been established.

Do not label an opportunity CONFIRMED based only on speculation, social-media rumours, or previous projects' reward history.

## 3. Verification records

Where available, maintain:
- Official project URL
- Direct evidence/source URL
- Last verified date
- Brief verification notes
- Current opportunity status
- Estimated costs and difficulty, clearly marked as estimates

Update records when the project changes its documentation, participation requirements, or program status.

## 4. Safety and financial disclaimers

Never ask users for seed phrases or private keys. Warn users to verify domains, transaction permissions, network fees, and token approvals before interacting with a project.

A testnet, node, or developer program does not guarantee tokens, NFTs, USDT, ETH, or any other compensation.

## 5. Corrections

If a listing is outdated or inaccurate, review the official source and update or remove the listing. Do not keep unsupported claims merely to maintain a large directory.
