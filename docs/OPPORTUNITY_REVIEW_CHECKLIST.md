# Opportunity Listing Review Checklist

Use this checklist before adding a listing or changing its status/incentive label. A listing is informational, not a promise of eligibility or profit.

## 1. Source quality
- [ ] Link to a project-controlled website, documentation page, official announcement, or official repository.
- [ ] Confirm the source describes the exact program listed, not just the project's existence.
- [ ] Prefer a direct announcement or current documentation page over a homepage.
- [ ] If only a community/forum post is available, label the evidence clearly and seek corroboration.

## 2. Program status
- [ ] Confirm whether participation is open, upcoming, paused, or ended.
- [ ] Check dates, supported regions, onboarding caps, and whether registration or node slots are still available.
- [ ] Do not infer that a testnet is incentivized just because it is active.
- [ ] Record the date checked in UTC and explain what was actually verified.

## 3. Incentive label
- **CONFIRMED:** an official or otherwise credible project source explicitly describes a reward, points campaign, token allocation, or incentive mechanism.
- **POTENTIAL:** there is a plausible reason to monitor the project, but no sufficiently clear reward announcement for this specific program.
- **NOT_ANNOUNCED:** no confirmed incentive announcement is recorded from the sources reviewed.

A confirmed incentive mechanism does not mean every participant will qualify or receive a reward. Never estimate token price, airdrop size, allocation, or personal earnings without reliable evidence.

## 4. Costs and safety
- [ ] Add an estimated cost only when there is a defensible source and a stated basis; otherwise leave it blank.
- [ ] Distinguish free testnet tokens from transferable or monetary-value assets.
- [ ] Mention meaningful hardware, bond, uptime, and network-fee requirements when the sources state them.
- [ ] Never tell users to share seed phrases, private keys, or pay unofficial agents.
- [ ] Flag security risks and tell users to verify software downloads and domains independently.

## 5. Before publishing
- [ ] Summary is factual, concise, and not promotional.
- [ ] Official URL and evidence/source URL are both valid and point to relevant pages.
- [ ] Verification notes state what the source proves and what remains unknown.
- [ ] Recheck any time-sensitive claim immediately before deployment.
- [ ] Remove or update listings when the program ends or evidence changes.
