# NodeDrops.xyz — Content Verification Policy

## 1. Source Quality
- Prefer official network documentation.
- Use official repositories for installation instructions.
- Record source URLs and review dates.
- Do not present unofficial claims as official facts.

## 2. Verification Statuses

### Source Reviewed
Official documentation and relevant instructions
have been reviewed. Practical execution is not implied.

### Setup Tested
The guide was executed in a documented environment.
Record the OS, hardware, client version and test date.

### Needs Review
Instructions may be outdated, incomplete or affected
by upstream changes.

### Retired
The network, software version or guide is no longer
recommended or supported.

## 3. Guide Requirements
Each guide should identify:
- Network and node type
- Prerequisites and supported OS
- Software versions
- Hardware and storage requirements
- Estimated costs and assumptions
- Installation and configuration steps
- Expected command output
- Health and synchronization checks
- Troubleshooting instructions
- Official references
- Verification status and review date

## 4. Rewards and Incentives
- Never promise tokens, NFTs or financial rewards.
- Link to official announcements and eligibility terms.
- Distinguish confirmed programs from unconfirmed speculation.
- Mark expired or ended programs accurately.
- State clearly when no reward is confirmed.

## 5. Mainnet Safety
- Never ask users to disclose private keys or seed phrases.
- Explain staking, downtime and slashing risks where relevant.
- Warn about public RPC exposure and insecure firewall rules.
- Explain backup, recovery and update procedures.
- Never claim a command is tested unless it was actually tested.

## 6. Publishing Workflow
1. Research official sources.
2. Draft the guide.
3. Review commands and configuration.
4. Test in the documented environment when possible.
5. Record verification evidence and date.
6. Publish with an accurate status.
7. Re-review after important upstream changes.

## 7. Corrections
Provide a way for users to report errors.
Review reported issues and update affected guides.
Keep revision history for important changes.
